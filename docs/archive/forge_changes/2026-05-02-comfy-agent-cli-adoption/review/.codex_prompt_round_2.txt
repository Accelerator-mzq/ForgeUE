# Round 2 adversarial focus

Two questions to answer:

QUESTION 1 — Is each round 1 finding ACTUALLY fixed by the writeback, or did the fix mis-target?

Specifically interrogate:

- F1 critical (cancel unreachable): writeback added D6 (lifecycle=none only) + new spec Requirement "ComfyAgentWorker cancel is best-effort under orchestrator to_thread wrapping" + assert in worker init + executor + bundle spec rejection. Did this REALLY fix cancel reachability, or did it just narrow the lifecycle scope and acknowledge the cancel hole as best-effort? Are there any cancel paths not covered (e.g. user Ctrl-C during shutil.copy2 in submit, where copy2 is sync IO inside the to_thread thread)?

- F2 high (alias missing model entry): writeback added providers.comfy_api + models["comfy/local"] virtual id + aliases.image_local. Does the bundle path actually resolve via this chain? The model id "comfy/local" uses slash but "comfy" is NOT the provider name (provider is "comfy_api"). Existing model ids (qwen/..., hunyuan/...) all use provider/model format with consistent prefix. Will CapabilityRouter prefix matching or ModelRegistry parsing trip on this naming inconsistency? Should the model id be "comfy_api/local" instead?

- F3 high (ADDED only): writeback added MODIFIED Requirements section updating "Non-OpenAI protocols ship dedicated adapters" (4 to 5 protocol families). Does the MODIFIED section copy the FULL original requirement block per OpenSpec instruction ("MODIFIED requirements MUST include full updated content")? Or did Claude rewrite the requirement text and add only ONE new scenario, leaving the original requirement structurally incomplete? Also: tasks §10.5 marks main spec line 25 Current Behavior for manual edit at archive time. Is "manual edit at archive" an acceptable workaround for OpenSpec MODIFIED's inability to modify Current Behavior / Invariants / Non-Goals sections, or is this a contract debt?

- F4 high (--project semantic split): writeback unified all 4 sites to task.project_id. But ComfyAgentWorker.__init__ signature in micro_tasks Step 3.2 has project_id: str | None = None (optional, defaults to None). If executor fails to pass it, worker constructs --project None which is meaningless. Should project_id be required (no default) or assert is not None?

- F5 high (dry-run 10s timeout): writeback gated probe by prepared_routes containing comfy_api + bumped timeout 10s to 30s. But where exactly is the prepared_routes hook point in DryRunPass? framework.workflows.loader expands models_ref into prepared_routes; does DryRunPass.run() see the expanded prepared_routes attribute or the raw bundle dict? tasks §4.3 says "DryRunPass detects" but provides no API surface confirmation. - F6 medium (test baseline 549): writeback removed hardcoded arithmetic, switched to "measured" wording in tasks §6.5 + §9.6. Sufficient as a fix?
